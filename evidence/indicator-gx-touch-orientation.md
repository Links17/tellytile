# Indicator GX touch orientation

The viewer reported that the bottom-left brightness key opened the top-right frame-rate menu. This identifies a 180-degree touch-to-display mismatch on the tested GX unit with an FT6336U controller. The GX FT6336U path now mirrors both axes about pixel 479 and leaves the GX GT911 and DX mappings alone. The app rejects out-of-range touch coordinates before processing gestures.

A host check compiled the real BSP against the CodeCraft touch fixtures and verified both controller families and both display profiles. The first correction brought the frame-rate button into alignment. Pressing the now correctly mapped brightness key exposed a separate fault: `ledc_set_duty_and_update` returned an error because the fade service had not been installed, causing the ESP32-S3 to restart. The follow-up changes the backlight duty through `ledc_set_duty` and applies it through `ledc_update_duty`. The updated image passed the native build and offline layout checks.

The updated app region was written and verified. The first boot hit a transient expander I²C timeout and restarted once. It then initialized the GX screen and FT6336U with `rotate_180=1` and resumed DW English playback. The user confirmed the brightness and frame-rate controls worked on the device. The serial trace logged brightness changes between 70% and 100% without the previous fade-service error. It also logged a later software restart after switching to the fixture channel. The cause of that separate restart was not determined.
